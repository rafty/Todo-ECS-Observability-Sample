# AGENTS.md

## 対象範囲
- このファイルは `load-test/` 配下に適用されます。

## 最初に確認すること
- `load-test/specs/` 配下の `specs.md` / `plan.md` / `tasks.md` を確認し、負荷試験要件と実装順序を把握してください。
- `docs/load-test/` および `docs/backend/api.md` を確認し、試験対象 API 契約と運用手順を把握してください。

## 作業ルール
- 負荷試験資材は `load-test/` 配下に集約し、用途ごとにディレクトリを分離してください。
- JWT、固定パスワード、認証情報などの機密データはリポジトリに保存しないでください。
- 生成物（`tokens.json`、ZIP、実行ログ）は再生成可能な扱いとし、恒久保存しないでください。
- スクリプトは再実行可能性を優先し、中断時の再開方針を実装または文書化してください。
- テスト対象環境は要件どおり `prod` 固定を前提にし、誤実行防止の確認項目を実装または文書化してください。
- 変更は要件範囲に限定し、無関係なリファクタリングや rename を避けてください。
- コードの処理単位毎に、必ずコメントに「なぜ必要か」を日本語で書いてください。
- コードに注意点があれば、必ず日本語でコメントを書いてください。
- コードに曖昧・危険な要件がある場合、`# TODO: 人間に確認が必要: <内容>` を追加し保守的な実装を優先してください。

## ディレクトリ運用
- `load-test/scripts/`: 前処理・補助スクリプト（ユーザー作成、JWT 生成、ZIP 作成など）
- `load-test/k6/`: K6 シナリオ本体とシナリオ補助モジュール
- `load-test/test-case/`: DLT 提出用 ZIP の出力先
- `load-test/specs/`: 要件・計画・タスク管理

## セキュリティ
- 実行ログにアクセストークンやパスワードを出力しないでください。
- ファイル出力時は権限と保存場所を制限し、不要になった生成物は削除してください。
- IAM 権限は最小権限を守り、`AdminInitiateAuth` を使う実行主体を限定してください。

## 検証
- 変更したスクリプトの構文検証（例: `python3.13 -m py_compile`）を実施してください。
- K6 シナリオ変更時は、可能な範囲で低負荷スモーク検証を実施してください。
- 実施できない検証は、未実施理由と未確認範囲を明記してください。

## ドキュメント更新
- 負荷試験手順を更新した場合は `docs/load-test/` を更新してください。
- 文書を追加・移動した場合は `docs/README.md` と必要な `README.md` の導線を更新してください。
- ドキュメントは必ず日本語で作成してください。

## 禁止事項
- シークレット、JWT、固定パスワード、認証情報のコミットを禁止します。
- `load-test/test-case/` への不要なバイナリ・巨大ファイルの恒久コミットを禁止します。
- 明示的な依頼なしに本番影響のあるインフラ設定を変更しないでください。
